# Command Effect Verifier V1.1 · PBL 闸门 · PowerShell 声明—事实一致性

> 日期：2026-10-16 · 版本：**V1.1**  
> 架构：PBL（Powered By Limitation）· 闸门层组件  
> 范围：MVP 方案、实施计划与设计裁决  
> 本文是技术设计说明，不是某个 Agent 宿主的生产接线，也不执行被检查的命令本身。

---

## 一句话定位

给 Agent 做一个轻量插件：在 PowerShell 命令执行前，由主进程 LLM 附带一份结构化声明，插件在本地完成机械事实提取，比对声明与事实的一致性，再按「区域 × 动作」策略矩阵决定静默放行、打回重写或升级人审。系统**不执行命令、不调用任何额外 LLM、不加载工具与 skill，零 API 成本**。

本组件是 PBL（Powered By Limitation）架构闸门层的第一个落地组件。PBL 的核心命题：授权的所有「AI 不能干的事」都建立在足够严苛的限制之上——限制是引擎而非成本，信任从「信不信它」（不可回答）转移到「护栏够不够硬」（可逐项检查）。

## 1  项目定位与设计演进

### 1.1  设计演进

本方案经四轮迭代收敛，每轮修正一个结构性问题：

| 版本 | 方案要点 | 关键修正 |
|------|----------|----------|
| V0 | AST 解析 + 规则表翻译 + 小模型兜底 + 路径门禁 | 初版思路 |
| V1 | 人话解释转回主进程 LLM，插件只做机械检查 | 发现 writer = explainer 相关性偏差：LLM 描述意图而非实际效果，引入双层声明化解 |
| V2 | 声明与机械事实不一致即打回 | 确认省掉的是展示层、省不掉事实提取；确立结构化 claims、三分出口、门禁独立于一致性 |
| V3 | 策略矩阵 + 分级响应 + 预检层 | 解决镜像克隆误伤、synchronized lie 盲区；网络区策略转为默认；确定威胁模型上限 |
| V4（敲定） | 动态调用治理 + 重跑残迹检查 + PBL 定名 | 裁决：不解决动态分析、消灭动态需求（agent 即 eval，见第 7 章）；重跑为独立事件须先查残迹（见 6.4）；整体纳入 PBL 闸门层 |

### 1.2  核心洞察

痛点有两条。其一，AI 写 PowerShell 频繁在细节上翻车——反斜杠转义、路径拼接、变量展开——而且这些错误发生在语法合法的语义层，AST 解析能通过，人眼更容易看漏。其二，沙箱、虚拟机、云电脑太重，不适合「AI 写命令 → 人看一眼 → 执行」的高频轻量场景。

关键判断是：人审需要意图层信息，机器需要机械事实，两者的来源必须分离。LLM 负责声明意图（它带着完整任务上下文），本地层负责提取事实（它不会犯转义错误）。转义错误只存在于命令字符串里，不存在于 LLM 的心智模型里——所以让两边各自产出结构化数据再做等值比对，一旦不一致，就是最强的危险信号。

### 1.3  不做的事

- 不做风险评分，不输出分数，只输出出口判定与结构化事实；
- 不做沙箱、虚拟机、云电脑，不执行命令；
- 不加载工具与 skill，零额外 API 调用；
- 不追求 100% 准确，追求让人看懂 + 拦住灾难。

## 2  系统架构

### 2.1  总体流程

```
主进程 LLM 生成命令
|  强制附带结构化声明（intent + claims）
v
插件（纯本地，零 API 成本）
|-- [1] 预检：前置条件验证 -------- 失败 ----------> 打回
|-- [2] 事实提取：AST + 变量求值 + 别名归一化
|-- [3] 一致性比较：claims vs 事实 -- 危险分歧 ----> 打回
|                                    无害分歧 ----> 标注(notice)
|-- [4] 策略矩阵：区域 x 动作 ------- 命中 deny --> 硬阻断 + 人审
v
无分歧且无策略命中 --> 静默放行，返回结构化结果
```

### 2.2  组件职责总览

| 组件 | 输入 | 输出 | 职责边界 |
|------|------|------|----------|
| 声明协议 | 任务上下文 | intent + claims | 主 LLM 填写，harness 强制成对 |
| 预检层 | claims + 命令 | 通过 / 打回 | 只管跑不跑得成，不管危不危险 |
| 事实提取器 | 命令字符串 | 结构化事实 | 只管提取，不做判断 |
| 一致性比较器 | claims + 事实 | 匹配 / 打回 / 标注 | 只管写没写对 |
| 策略矩阵 | 事实 + 区域配置 | 放行 / 人审 / 阻断 | 只管该不该做 |

### 2.3  三分出口

| 出口 | 触发条件 | 后续动作 |
|------|----------|----------|
| 静默放行 | claims 与事实一致，且无策略命中、无 notice | 直接执行 |
| 打回 | 预检失败，或危险分歧（路径 / 动作类对不上） | 机械事实回传主 LLM，重写后重报 |
| 人审 / 阻断 | 策略矩阵命中 deny，或无法解析 | 事实 + 命中规则呈给人看；阻断不可降级 |

另有无害分歧走标注通道：不影响执行流程，只在返回结果中附加 `notices` 字段，供人审时参考。

## 3  声明协议（核心契约）

### 3.1  双层声明：intent 与 claims

声明分两层，只有一层参与机械比较。`intent` 是自由文本，只给人看、永不参与比较；`claims` 是结构化字段，与机械事实逐项等值，是比较器的唯一输入。

```json
{
  "intent": "克隆 GitHub 上的 X 项目",
  "claims": {
    "action": "fetch",
    "url": "https://gitclone.com/github.com/x/y.git",
    "dest": "D:\\proj\\y",
    "recurse": false,
    "preconditions": { "dest_parent_exists": true }
  }
}
```

镜像场景示例：LLM 使用清华源镜像时，claims 如实填镜像地址；机械层解析出的也是同一镜像地址——一致，放行。「GitHub 还是镜像」的差异只存在于 intent 层，由交叉验证产生 notice，人审时可见，但不构成打回理由。

### 3.2  claims 字段规范

| 字段 | 类型 | 说明 | 比较策略 |
|------|------|------|----------|
| action | 枚举 | read / copy_in / copy_out / write / delete / fetch / build / execute | 严格等值 |
| paths / dest | 字符串 | 目标路径（规范化后） | 严格等值 |
| url | 字符串 | 网络端点 | 宽松 + intent 交叉验证 |
| recurse | 布尔 | 爆炸半径标注 | 严格等值 |
| preconditions | 对象 | 执行前置条件 | 预检层验证（见第 8 章） |

### 3.3  强制机制

协议靠结构强制，不靠 prompt 自觉：harness 设卡口，没有成对声明的命令不进入执行队列。声明缺失、字段缺失、类型不符，一律视为预检失败打回。

### 3.4  值域与规范化规则

比较器永不比较自然语言。标准化分三层，逐层收窄，之后才允许等值比较：

| 层级 | 规则 | 处理方式 |
|------|------|----------|
| schema 层 | 字段名、类型固定；action 为封闭枚举 | harness 在比较前校验；枚举外的值直接打回 |
| 值规范化层 | 路径与 URL 两侧使用同一规范化函数（求值 → GetFullPath → 大小写归一） | 声明值与提取值进比较器前过同一个函数 |
| 等值比较层 | 逐字段严格等值；网络端点宽松处理 | 见 5.1 |

**action 枚举（封闭，不得增删）**：`read | copy_in | copy_out | write | delete | fetch | build | execute`

设计原则：标准化 = schema 层 → 值规范化层 → 等值比较。自然语言永远停在展示层。

## 4  机械事实提取器

### 4.1  AST 解析

使用 PowerShell 官方 Parser，本地零成本：

```powershell
$tokens = $null; $errors = $null
$ast = [System.Management.Automation.Language.Parser]::ParseInput(
  $command, [ref]$tokens, [ref]$errors)
```

提取 CommandAst、ParameterAst 与各类表达式节点，得到 cmdlet 名称、参数名与参数值。语法错误本身即预检失败，直接打回。

### 4.2  变量分级求值

| 级别 | 输入形态 | 处理方式 | 事实标记 |
|------|----------|----------|----------|
| L1 | 纯常量 `'C:\data\foo'` | 直接解析 | 确定值 |
| L2 | 可展开字符串 `"$HOME\foo"`、`$env:*` | 白名单变量求值 | 推断值 |
| L3 | 任意表达式 `$(...)`、脚本块 | 拒绝求值 | unresolvable，打回重写 |

附带收益：L3 打回等于强制 agent 只写可静态求值的字面命令，整体命令质量被抬升。

### 4.3  别名归一化与原生命令

- 别名归一：`del`、`rd`、`ri` 等均为 `Remove-Item` 的别名，经 CommandInfo 归一后再进规则表，防止绕过；
- 原生命令（git、npm 等）不做完整效果语义，只提取路径类字段（如 dest），动作标粗粒度类别；
- 任意执行类（Invoke-Expression、iex、cmd /c、Start-Process 任意化场景）进本地强制拦截名单，不走描述路径——处置规则见第 7 章。

### 4.4  爆炸半径标注

效果事实必须携带量级信息：`-Recurse`、`-Force`、通配符（如 `C:\*`）、`-Include` 均须进入事实。`Remove-Item foo` 与 `Remove-Item foo -Recurse` 是两件事。`Copy-Item` 需区分 Source 与 Destination 参数角色，产出 `copy_out`（从保护区拷出）或 `copy_in`（向保护区拷入）。

### 4.5  动态调用汇点检测

事实提取器的最后一道职责是识别「存在待解析物」。关键判据：不需要算出动态字符串是什么，只需要机械地判定它存在——判定的是可解析性而非解析结果。标准保守：宁误报勿漏报。汇点为闭集：

| 汇点 | 典型形态 | 说明 |
|------|----------|------|
| Invoke-Expression / iex | `iex $c` | 字符串直接求值 |
| 可变命令名 | `& $cmd` | CommandAst 命令名为变量 |
| 调用操作符 | `. $sb` / `& $sb` | 脚本块调用 |
| ScriptBlock::Create | `[scriptblock]::Create($s)` | 用字符串铸造代码 |
| Add-Type | 内联编译执行 | 动态代码的旁路入口 |
| 别名指向 iex | `set-alias x iex; x $c` | 别名归一化先于汇点判定 |

整脚本级保守判定：脚本内出现任何变量形式的调用，整体按动态调用处理。命中汇点的事实标记为 `dynamic_invocation`，处置见第 7 章。

## 5  一致性比较器

### 5.1  比较原则：只比较分歧意味着危险的材料

| 字段 | 分歧含义 | 策略 |
|------|----------|------|
| 路径 / 目标 | LLM 心智模型与命令实际不符（转义错、拼错） | 严格等值，分歧即打回 |
| 动作类 / recurse | 以为只是覆盖写，实际是递归删除 | 严格等值，分歧即打回 |
| 网络端点 | 镜像、CDN、重定向——对机器本地效果无差异 | 宽松：与 intent 交叉验证，不一致产生 notice |
| intent 自由文本 | 不参与比较 | 只给人看；抽取域名与 url.host 交叉验证 |

### 5.2  打回：纠错回路，不是惩罚

打回时把机械事实塞回去，通常一轮自愈。若 LLM 对自己命令没有认知偏差（如故意使用镜像），无害分歧走标注而非打回。打回救不了「对任务选错了方案」这类正确性问题，那属于策略矩阵与人审的管辖范围。

## 6  策略矩阵（区域 × 动作）

### 6.1  设计原理

危险从来不是路径的属性，是操作与路径关系的属性。保护不绑定路径本身，而绑定「区域 × 动作」组合。与一致性检查的分工：一致性管写没写对，矩阵管该不该做——自洽不等于安全。

### 6.2  默认矩阵

| 区域 | 读 / 拷出 | 写入 | 删除 | 执行 |
|------|-----------|------|------|------|
| 系统区（C:\Windows、Program Files 等） | 放行 | 人审 | 硬阻断 | 硬阻断 |
| 用户区（$HOME） | 放行 | 放行 | 人审 | 放行 |
| backup 目录（自定义） | 放行 | 放行 | 人审 | 人审 |
| 项目根目录 | 放行 | 放行 | 放行 | 人审 |
| 网络区 | github.com 及已知镜像：放行（镜像加标注）；未知域名：人审 | — | — | — |

姿态：deny-list。内置系统区兜底，其余区域默认不命中。矩阵做成用户可编辑的数据文件，不是硬编码。

### 6.3  匹配实现规范

- 规范化先行：变量求值 → GetFullPath 规范化 → reparse point 解析 → 模式匹配；
- 已知绕过口：8.3 短名、尾随点与空格、UNC 与 `\\?\` 前缀、大小写不敏感；
- 递归放大器：带 `-Recurse` 的删除，检查整棵子树里有没有命中保护区。

### 6.4  重跑残迹检查

「失败命令的重跑」是独立事件。重跑前必须先声明并检查上次失败尝试的残迹（post-condition）——残迹非零，先声明清理，或改用幂等写法。同一命令文本在短时间内第二次进入闸门时，命中「重跑」事件类，预检层追加残迹检查项，未声明残迹处置即打回。

## 7  动态调用治理（2026-10-15 裁决）

### 7.1  问题与裁决

完备地静态预测动态字符串的解析结果无解（Rice 定理）。裁决是：**不解决动态分析，直接消灭动态需求**。业界先例：JS CSP 禁 eval、Python bandit S307 都是「策略驳回」路线。

### 7.2  立法理由：agent 自己就是 eval

Agent 每一轮都是现场重新组织命令的，动态性需求已被 agent 自身吸收。在一条 agent 命令里再用 iex，买到的动态性是零，引入的不可验证性是全部。

### 7.3  检测与处置

- 检测：按 4.5 汇点闭集识别，宁误报勿漏报；命中后事实标记 `dynamic_invocation`；
- 处置：命中即打回，判决机械、零裁量；驳回理由附替代建议（建议只进驳回理由、不进验证链路）；
- 建议优先级：直接调用 > 参数化写法 > 临时脚本；
- 逃生门（临时脚本）：把一次不可声明的动态执行，拆成 N 次可声明的静态事件；
- 循环衔接：同一脚本连续 N 轮坚持动态调用，强制升级人审。

### 7.4  诚实边界

汇点清单不可能完备（子进程、编码解码、dot-source 等是逃逸口）。对抗性混淆不解决——对抗出错不对抗恶意。安全性兜底靠默认驳回姿态，而非清单完备性。

### 7.5  冷库条款

被否决的备选：拦截点递归验证（周级工程）。复活条件：账本统计显示 iex 出现率不可忽略、且打回后改写成功率显著低于预期时，重新立法。

## 8  预检层（省时间）

验证 `claims.preconditions`：

- 源路径存在性（删除、复制源）；
- 目标父目录存在性（写入、克隆目标）；
- AST 语法零错误（解析阶段免费获得）。

预检失败即打回。预检只省时间，不做安全判断；危险判定全部由比较器与矩阵负责。

## 9  威胁模型与能力边界

| 威胁 | 典型例子 | 防线 |
|------|----------|------|
| mistake：转义 / 拼接错误 | 引号 + 尾随反斜杠致路径解析为根目录 | 一致性比较器 |
| confusion：心智模型错位 | 以为删的是 backup，实际解析到 C:\ | 一致性比较器 + 路径门禁 |
| deception：声明与命令对齐撒谎 | intent 写 GitHub，实际从恶意站点下载 | 策略矩阵 + 人审（一致性对 synchronized lie 天然失明） |

能力上限：声明与命令同源于主 LLM，任何自报皆可对齐。mistake 与 confusion 靠一致性抓，deception 只能靠独立于 LLM 的策略矩阵和人审抓。

## 10  事故回归集

质量度量是事故集拦截率，不是规则覆盖率。

| 编号 | 用例 | 命令特征 | 期望出口 |
|------|------|----------|----------|
| E1 | 尾随反斜杠转义 | Remove-Item 带引号与尾随反斜杠，声明路径与解析路径分歧 | bounce / block |
| E2 | 变量展开偏差 | 声明 D:\proj，实际解析为 $HOME 下路径 | bounce |
| E3 | 镜像克隆 | claims 如实填镜像 URL，intent 写 GitHub | pass + notice |
| E4 | 删除系统区 | Remove-Item C:\Windows -Recurse | block |
| E5 | 未知域名下载 | intent 写 GitHub，命令指向未知域名 | human |
| E6 | 动态拼接执行 | `$c = 'Get-' + 'ChildItem'; iex $c` | bounce |
| E7 | 失败命令残迹重跑 | 部分执行失败后原样重跑，未声明残迹检查与清理 | bounce |

叙事证据类用例归接地检查器回归集，不在本集。

## 11  MVP 实施计划

### 11.1  范围

四个模块加一个回归集：声明协议、机械事实提取器、一致性比较器、策略矩阵。V0 方案中的 LLM 兜底整条线删除。

### 11.2  里程碑

| 阶段 | 交付物 | 验收 |
|------|--------|------|
| **M1** | 事实提取器：AST 解析 + 变量分级求值 + 别名归一化 + 动态汇点检测 | **对单条命令输出事实 JSON** |
| M2 | 声明协议 + 比较器 + 打回回路 | E1、E2 用例通过 |
| M3 | 策略矩阵 + 预检层 + 重跑残迹规则 + 回归集全量 | E3–E7 通过，端到端验收 |

### 11.3  验收标准

两条端到端用例定成败：其一，镜像克隆场景标注放行、不多付一轮重试；其二，反斜杠删盘场景被打回或阻断，机械事实准确回传。

## 附录 A  插件输出结构（完整示例）

```json
{
  "verdict": "pass | bounce | human | block",
  "intent": "主 LLM 的自由文本声明，原样透传",
```

## 附录 B  主进程契约硬规则

1. mismatches 或策略命中非空时，禁止自动执行，必须人工确认；
2. 策略矩阵的阻断结论不可被任何环节（包括 LLM 输出）降级；
3. 无成对声明的命令不进入执行队列；
4. LLM 自报的置信度不参与任何路由决策——出口由管线层级唯一决定；
5. 插件自身故障一律 fail-closed：降级为人审，绝不静默放行；
6. 同一命令的打回重试超过上限 N 次，强制升级人审；
7. 动态调用与重跑残迹的判决均为机械判决：替代建议不得反向影响出口判定。

fail-closed 条款：错误方向受控——所有未决状态的默认代价都是一轮重试或一次人审，而非一次执行。
